## 3. 开发原则

1. 每次只引入一个可验证的功能链路。
2. 先验证原始数据，再实现控制算法。
3. 驱动层不直接依赖业务状态机，应用层负责数据组织和故障判断。
4. 所有周期任务使用固定周期运行，避免在任务中使用长时间阻塞延时。
5. 每个阶段都记录实际硬件现象、串口输出和未解决问题。

## 4. 阶段一：整理正式启动链路

### 目标

让系统启动后进入正式应用初始化，而不是运行 CubeMX 默认输入测试任务。

### 主要工作

- 在 `main.c` 中保留 HAL、时钟和 CubeMX 外设初始化。
- 调用 `OLED_Init()`，并处理 OLED 初始化失败状态。
- 调用 `App_Init()`，统一初始化 BSP 和基础组件。
- 在 `App_Init()` 中启动 ADC DMA、PWM/测速相关底层资源。
- 调用 `Tasks_Init()` 创建正式任务和通信对象。
- 删除或停用 `freertos.c` 中的 `defaultTask` 输入测试逻辑。
- 将按键、编码器初始化移动到正式 UI 任务或统一应用初始化流程。

### 验收标准

- 上电后无 10 秒级阻塞测试。
- 串口能看到一次完整的系统初始化日志。
- FreeRTOS 中运行的是应用任务，而不是输入测试任务。
- OLED 能显示启动状态，初始化失败时不会导致系统死循环。

## 5. 阶段二：完成电机开环和测速链路

这是后续 PID 开发前最重要的验证阶段。

### 目标

完成以下最小闭环链路中的开环部分：

```text
设置 PWM 占空比
    -> 电机运行
    -> 光电传感器产生脉冲
    -> TIM3 捕获周期
    -> 计算 RPM
    -> USART1 输出结果
```

### 主要工作

- 在 `bsp_timer.c` 中增加 TIM3 捕获周期保存变量。
- 实现 `HAL_TIM_IC_CaptureCallback()`，读取相邻两次捕获值。
- 正确处理定时器计数器溢出。
- 根据定时器计数频率和传感器每转脉冲数计算 RPM。
- 增加无脉冲超时判断，避免电机停止后保留旧转速。
- 在 `bsp_pwm.c` 中确认占空比计算边界，验证 0、最小启动占空比和最大占空比。
- 完成电机使能和方向控制，确认 `PC7`、`PC9` 的有效电平。
- 通过串口周期输出：占空比、捕获周期、脉冲频率、RPM 和测速有效标志。

### 验收标准

- 占空比为 0 时电机停止，PWM 输出符合预期。
- 给定固定占空比时，RPM 输出随电机转速变化。
- 手动遮挡或停止光电传感器后，RPM 能在规定超时时间内归零或置为无效。
- 连续运行 5 分钟无捕获异常、计数溢出错误或任务阻塞。

## 6. 阶段三：完成 ADC 和传感器数据层

### ADC 方案

当前继续采用“四通道扫描 + 循环 DMA”。这是现阶段更合适的方案：硬件配置已经可用，CPU 占用低，四个通道可同时保留，传感器任务每 100 ms 读取一次即可满足油烟浓度和风速的初步控制需求。

暂不切换为定时器触发 ADC。定时器触发适合后续需要严格采样频率、同步采样或更高数据一致性的版本，但会增加定时器资源和 CubeMX 配置复杂度。

### 主要工作

- 定义统一的 `SensorData_t` 数据结构，至少包含：原始 ADC、电压、温湿度、气压、气体浓度、风速、时间戳和有效标志。
- 在 `Task_Sensor` 中每 100 ms 读取 ADC DMA 数据。
- 为 ADC 数据增加简单均值滤波或一阶低通滤波。
- 完成 SHT30 和 BMP280 的初始化、读取、CRC/校准失败处理。
- 完成 MQ135 预热状态和“未校准”状态标志，不把简化 ppm 当作精确计量值。
- 对 I2C 设备地址统一使用 HAL 所需的地址格式，并通过实际应答确认。
- 将有效的 `SensorData_t` 发送到传感器队列。

### 验收标准

- 串口能周期输出四路 ADC、电压、温湿度、气压和风速。
- 传感器断开、CRC 错误或数据越界时能标记无效。
- 传感器任务不会因单次 I2C 超时永久阻塞。
- 数据队列不会因生产速度和消费速度不匹配而失控。

## 7. 阶段四：实现 FreeRTOS 任务通信

### 主要工作

- 将队列元素从临时 `uint32_t` 改为明确的数据结构。
- 传感器任务只负责采集、滤波和发布数据。
- 电机控制任务只负责读取目标转速、当前 RPM、执行控制器和输出 PWM。
- UI 任务负责按键、编码器和 OLED 更新。
- 系统管理任务负责状态机、故障标志和模式切换。
- 使用 I2C 互斥量保护 OLED 和传感器总线。
- 删除各任务中的高频 `printf`，日志统一由日志任务或限频接口输出。

### 验收标准

- 各任务按既定周期运行：电机控制 50 ms，传感器 100 ms，UI 100 ms。
- 队列和互斥量创建失败时有明确错误处理。
- 任务之间不直接访问彼此的私有状态。
- 高负载时 OLED 更新不会阻塞电机控制任务。

## 8. 阶段五：实现手动模式和 PID 转速控制

### 主要工作

- 先实现手动模式：编码器调整目标转速，按键完成启停和模式切换。
- 明确目标转速范围、最小启动占空比和最大安全转速。
- 在 `Task_MotorControl` 中以固定 50 ms 周期调用 `PID_Update()`。
- 为 PID 增加 `dt <= 0` 保护、输出限幅和积分抗饱和。
- 使用实际测速周期计算 `dt` 或使用任务固定周期，二者必须统一。
- 转速无效、超速或电机使能关闭时强制停止 PWM。
- 通过串口记录目标 RPM、实际 RPM、误差、PID 输出和故障状态。

### 验收标准

- 手动设定目标转速后，电机能稳定运行并接近目标值。
- 改变目标转速时无明显失控或输出溢出。
- 电机堵转、测速丢失时系统能停止或进入故障状态。
- PID 参数可集中配置，不能散落在任务代码中。

## 9. 阶段六：实现自动模式和状态机

### 建议状态

- `IDLE`：待机，电机关闭。
- `MANUAL`：用户设定转速。
- `AUTO`：根据气体浓度、风速或温度调整目标转速。
- `BOOST`：爆炒或强排模式，使用限定的高目标转速。
- `FAULT`：关闭电机并显示故障原因。

### 主要工作

- 明确定义每个状态的进入条件、退出条件和允许动作。
- 自动模式使用经过滤波且有效的数据。
- 传感器失效时禁止自动模式继续升速。
- 加入转速上限、温度上限、测速丢失和电机堵转判断。
- 使用 OLED 显示当前模式、目标转速、实际转速和主要故障。

### 验收标准

- 模式切换不会产生异常 PWM 脉冲或任务阻塞。
- 故障状态下电机关闭，故障原因可追踪。
- 自动模式不会因单个异常采样瞬间跳到最大转速。

## 10. 阶段七：完善输入、显示和输出驱动

### 主要工作

- 根据实际硬件确认 PC2、PC3、PC4 是上拉还是下拉，以及按下有效电平。
- 统一按键 GPIO 配置、EXTI 边沿和 `button.c` 中的 `active_high` 逻辑。
- 完成 `Bsp_LED_Set()`、`Bsp_LED_Toggle()`、`Bsp_Motor_Enable()` 等 BSP 空实现。
- OLED 更新采用固定刷新周期，避免每个任务直接刷新整屏。
- 蜂鸣器只在模式切换和故障事件中触发，不在控制循环中反复触发。

## 11. 阶段八：参数、看门狗和故障记录

### 主要工作

- 增加 PID 参数、转速限制和模式配置结构。
- 选择 Flash 参数保存格式，增加版本号和校验值。
- 实现任务心跳和硬件独立看门狗。
- 记录最近一次故障类型、发生时间和关键测量值。
- 对启动失败、传感器异常和电机异常提供降级行为。

## 12. 每阶段通用验收记录

每完成一个阶段，至少记录以下内容：

- 使用的固件版本和 CubeMX 配置版本。
- 实际接线和供电情况。
- 串口关键输出。
- 示波器或万用表测得的 PWM、电压和信号频率。
- 正常场景、异常场景和恢复场景的结果。
- 尚未解决的问题及其影响范围。

## 13. 推荐的近期执行顺序

当前下一步按以下顺序实施：

1. 整理 `main.c`、`app_main.c` 和 `freertos.c` 的正式启动链路。
2. 完成 TIM3 捕获回调、周期保存、RPM 计算和无脉冲超时。
3. 完成 PWM、使能、测速的电机开环验证。
4. 建立统一 `SensorData_t` 和传感器任务数据流。
5. 完成手动模式和 PID 转速闭环。
6. 再实现自动模式、故障状态机、OLED UI 和参数保存。

在第 2～3 步没有通过前，不建议继续调 PID 或开发自动模式，因为没有可靠的实际 RPM 反馈，后续控制结果无法判断。
