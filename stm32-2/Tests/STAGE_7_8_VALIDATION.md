# 阶段 7/8：看门狗、持久化与异常记录

本阶段实现代码和主机验证，上板结果由用户补充。主机测试不能证明实际 IWDG 时序、Flash 电气掉电行为或异常恢复已经验收。

## 看门狗与心跳

- `Application/heartbeat.c` 使用 HAL 毫秒时钟，支持 uint32 回绕；各任务只报告自己的心跳，Idle hook 不阻塞。
- `Task_Watchdog` 优先级最高，每 100 ms 检查一次；仅所有监控任务已运行且未超时时刷新 IWDG。
- 从 `Tasks_Init()` 完成启动 Flash 操作、开始创建任务时起计，未首次报告的任务有 5000 ms 启动宽限；已报告的任务立即按自己的超时监控。
- 心跳超时立即关闭电机、记录缺失位图并软件复位。CPU 卡死、调度器卡死或关中断时，由 IWDG 最终复位。
- IWDG 分频 128，Reload=1999，32 kHz LSI 下约 8 s；实际时间按 `128 * 2000 / f_LSI`，必须测量 LSI 偏差和擦除最坏耗时。

| 心跳位 | 任务 | 正常周期 | 超时 |
| --- | --- | --- | --- |
| 0 | MotorCtrl | 50 ms | >250 ms |
| 1 | Sensor | 100 ms | >500 ms |
| 2 | UI | 输入 10 ms，显示分页 100 ms | >500 ms |
| 3 | SysMgr | 100 ms | >500 ms |
| 4 | Logger | 1000 ms | >2500 ms |
| 5 | Storage | 100 ms | >500 ms |
| 6 | Idle | 调度空闲时 | >500 ms |
| 7 | Watchdog | 100 ms | >1500 ms |

## 参数掉电保存

| 区域 | 地址 | 大小 |
| --- | --- | --- |
| 应用程序，扇区 0..5 | 0x08000000..0x0803FFFF | 256 KB |
| 日志 Bank 0，扇区 6 | 0x08040000..0x0805FFFF | 128 KB |
| 日志 Bank 1，扇区 7 | 0x08060000..0x0807FFFF | 128 KB |

目标芯片为 512 KB Flash 的 STM32F411RE。链接脚本将应用程序限制在前 256 KB，避免覆盖日志。下载固件时整片擦除会清空配置和故障；保留数据需只擦除应用扇区。

- `SystemConfig_t` 保存手动目标、最大目标、PID Kp/Ki/Kd、气体趋势电压阈值和延时关机参数。`shutdown_delay_ms` 已接入余烟排风及设置页面，见 `COMPLETE_MODES_UI_VALIDATION.md`。
- 上电校验格式、CRC 和参数范围；无有效配置则使用默认值。运行模式、启动意图不持久化，上电始终待机。
- `Tasks_SetConfig()` 校验参数并入队，SysMgr 同步应用并停机；按键改变手动目标不隐式启停。
- 配置连续 2 s 未修改且电机自然停机后，Storage 申请维护窗口；MotorCtrl 确认关闭输出，Watchdog 在健康且已喂狗的周期授予保存许可。
- Storage 持有配置锁、暂停任务调度后擦写；每窗口最多一个故障和一个配置，失败至少 5 s 后重试。Flash 事务期间禁用并刷新数据缓存，确保回读校验一致。
- 单 Bank 擦写期间代码取指可能暂停，中断/tick 也可能延迟。完成后重置心跳时间基线，保留已报告位图；维护任务不自行喂狗。故障时 IWDG 仍独立运行。
- `Tasks_GetConfig()` 取得当前快照；`Tasks_IsConfigSaved()` 为 true 才说明当前配置已成功保存且没有排队更新。立即断电或持续运行可能丢失尚在 RAM 中的修改，保留之前已提交的配置。

每条日志固定 256 B：magic/type/version/length/sequence 共 20 B，payload 224 B，搬移标识 reserved 4 B，CRC32 4 B，最后 commit 4 B。CRC 覆盖前 248 B，commit 最后写入；半写记录不会作为有效配置。

扇区满时，只擦除非当前扇区，搬移最新参数和故障，保留原序号并标记副本；新记录完整提交后才切换当前扇区。旧扇区在下一次搬移前保留。配置不变不追加记录，每扇区有 512 个槽，搬移后最多保留 2 条副本。

## 故障记录与系统异常

- 故障队列容量 8，保存电机故障变化、传感器新错误；故障待停机后落盘。传感器事件队列满时可能丢弃，电机关键事件入队失败进入安全复位路径。
- `Tasks_GetLastFault()` 返回最近一次已落盘故障；启动串口输出 `[LAST_FAULT]`。目前未提供历史遍历、清除命令或 PC 协议。
- `FaultRecord_t` 保存原因、详情、运行时间、模式、RPM/目标/占空比、传感器标志及温度；异常记录追加 R0/R1/R2/R3/R12/LR/PC/xPSR、EXC_RETURN、CFSR/HFSR/DFSR/MMFAR/BFAR/AFSR 等寄存器。
- 原因编号 1..12：电机、传感器、心跳、HardFault、MemManage、BusFault、UsageFault、栈溢出、malloc 失败、启动失败、IWDG 复位、NMI。栈溢出的 detail 为任务句柄；心跳的 detail 为缺失位图。
- 栈溢出检查级别 2，启用 malloc 失败 hook；MemManage/BusFault/UsageFault 独立异常启用。
- 异常入口使用独立的 1024 B 安全栈。先通过 GPIOC PC7 关闭使能并关闭 TIM1 CH3N，再保存现场、复位；不在异常上下文操作 Flash、RTOS 队列或 printf。
- 异常邮箱位于 `.noinit` SRAM，以 CRC32 和提交标志保护。暖复位后先落盘，再清除邮箱；存储启动失败不覆盖未落盘异常。POR/BOR 时清除不可靠的 SRAM 邮箱。
- 原始栈帧需要 RAM 边界、对齐及压栈/退栈状态检查，支持 FPU 扩展帧；`frame_valid=0` 时 PC/LR 不可用。
- `.noinit` 只能跨暖复位保存；异常后、重启落盘前再次掉电可能丢失该次异常。尚在 RAM 队列里的运行故障同样不保证掉电保留。

## 软件验证

运行 `Tests/run_host_tests.ps1`，使用现有 LCC64 编译正式算法、组件和 BSP；Flash 使用内存后端模拟。

| 测试组 | 通过断言数 |
| --- | --- |
| GPIO/按键/开环 | 112 |
| 测速/PWM/电机，PPR=1 | 67 |
| 测速/PWM/电机，PPR=2 | 67 |
| PID/状态机/滤波/安全 | 275 |
| 配置/持久化/心跳 | 41114 |
| 传感器驱动 | 73 |
| 完整模式/UI/蜂鸣器 | 416 |
| 总计 | 42124 |

持久化测试覆盖：每个 word 边界直接模拟掉电（跳过失败清理）、word 前 0..3 字节写入后掉电、payload/CRC/commit 半写、两个类型同时搬移、正反扇区切换、损坏旧槽、每 4 B 擦除进度中断、重新扫描及重试保存。另覆盖 CRC 损坏回退、非法配置默认回退、不变配置免写、故障重启读取、序号回绕和心跳时钟回绕。

该模型验证恢复算法；真实 Flash 的随机位损坏、供电下降和 RTOS 维护窗口需上板测试。硬件异常汇编、SRAM 邮箱保留及 IWDG 无主机运行测试。

Debug 构建命令：`cmake --build build/Debug -j 4`（本机使用 STM32Cube 随附 CMake 完整路径）。构建通过，无新增编译警告/错误；RAM 28096 B，Flash 90528 B，占应用 Flash 区域 34.53%。产物为 `build/Debug/stm32-2.elf`。完整模式和交互的行为验收见 `COMPLETE_MODES_UI_VALIDATION.md`。
